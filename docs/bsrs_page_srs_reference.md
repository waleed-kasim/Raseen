# BSRS — نظام التكرار المتباعد للصفحات
### أداة القرآن الكريم | مرجع تقني شامل

---

## نظرة عامة

**BSRS (Bounded Spaced Repetition System)** هو محرك تكرار متباعد مخصص لحفظ صفحات القرآن الكريم. مبني على أساس خوارزمية SM-2 الكلاسيكية ومُطوَّر بإضافة:

- **نظام النطاقات (Zones):** تقسيم معامل السهولة إلى 5 مناطق مرتبطة بالتقييم
- **القفز الثنائي الاتجاه:** مضاعفة الفترة عند تخطي النطاقات صعوداً أو هبوطاً
- **الاختيار متعدد الحوضات:** تصنيف الصفحات في حوضات ذات أولويات مختلفة
- **عتبة اليوم:** ضمان عدم تكرار الصفحة أكثر من مرة يومياً

هذا المستند يغطي **SRS الصفحات فقط** — دالتا `getSmartPage` و `saveSRS`.

---

## 1. نموذج البيانات

كل صفحة تُخزَّن بسجل SRS خاص بها بمفتاح `page-{رقم}`:

```json
{
  "interval": 7,
  "reps": 4,
  "easeFactor": 2.6,
  "failureCount": 1,
  "history": [5, 4, 5, 3, 5],
  "lastReview": 1715593200000,
  "nextReview": 1716198000000,
  "isBesieged": false
}
```

| الحقل | النوع | الوصف |
|-------|-------|-------|
| `interval` | عدد | الأيام حتى المراجعة التالية |
| `reps` | عدد | عدد المراجعات الناجحة المتتالية |
| `easeFactor` | عشري | معامل السهولة (من 1.3 إلى 3.0) |
| `failureCount` | عدد | مجموع مرات التقييم 1 أو 2 |
| `history` | مصفوفة | آخر 10 تقييمات (حلقة دائرية) |
| `lastReview` | timestamp | وقت آخر مراجعة |
| `nextReview` | timestamp | أقرب وقت يمكن فيه اقتراح الصفحة |
| `isBesieged` | منطقي | يُضبط بواسطة كشف المحاصرة |

## 2. الثوابت

```
INITIAL_EASE:      2.3   — معامل السهولة الابتدائي لكل الصفحات
MIN_EASE:          1.3   — الحد الأدنى المطلق
MAX_EASE:          3.0   — الحد الأقصى المطلق
BASE_MAX_INTERVAL: 180   — سقف الفترة الأساسي بالأيام (يتمدد مع الاستقرار)
```

## 3. نطاقات التقييم

فضاء معامل السهولة مقسَّم إلى 5 نطاقات مرتبطة بالتقييمات الخمسة:

```
النطاق 5 — ممتاز :  EF ∈ [2.6, 3.0]،  إزاحة = +0.25
النطاق 4 — سهل   :  EF ∈ [2.2, 2.6]،  إزاحة = +0.10
النطاق 3 — جيد   :  EF ∈ [1.8, 2.2]،  إزاحة = −0.05  ← تعديل انحياز التفاؤل
النطاق 2 — صعب   :  EF ∈ [1.5, 1.8]،  إزاحة = −0.15
النطاق 1 — نسيت  :  EF ∈ [1.3, 1.5]،  إزاحة = −0.30
```

بعد تطبيق الإزاحة، يُطبَّق **تثبيت حاد (Hard Clamp)** يُسنِد معامل السهولة فوراً إلى حدود نطاق التقييم الجديد:

```
EF_جديد = clamp(EF_قديم + إزاحة، نطاق.min، نطاق.max)
```

**مثال:** تقييم "ممتاز" وEF في النطاق 1:
- `1.3 + 0.25 = 1.55` → يُسنَد إلى `2.6` (أدنى حد لنطاق 5) مباشرة

## 4. حساب المراجعة التالية — خطوة بخطوة

### الخطوة 1 — تحديث السجل التاريخي
يُضاف التقييم الجديد إلى حلقة السجل (آخر 10 تقييمات).

### الخطوة 2 — تحديث معامل السهولة
```
config  = BOUNDARIES[grade]
EF_جديد = clamp(EF_قديم + config.shift, config.min, config.max)
EF_جديد = clamp(EF_جديد, 1.3, 3.0)  // ضمان عالمي
```

### الخطوة 3 — حساب الفترة والتكرارات

| الحالة | الفترة | التكرارات |
|--------|--------|-----------|
| grade ≥ 3 وreps = 0 | 1 يوم | 1 |
| grade ≥ 3 وreps = 1 | 3 أيام | 2 |
| grade ≥ 3 وreps ≥ 2 | `round(فترة × EF_جديد)` | +1 |
| grade < 3 (فشل) | 1 يوم | **إعادة ضبط إلى 0** |

### الخطوة 4 — مضاعف القفز بين النطاقات (ثنائي الاتجاه)
بعد حساب الفترة الأساسية، يُفحص إذا كان EF قد تخطى أي حد نطاق:

```
نطاق_قديم = getZone(EF_قديم)   // 1–5
نطاق_جديد = getZone(EF_جديد)   // 1–5
الفرق     = نطاق_جديد − نطاق_قديم
```

| الفرق | شرط التقييم | التأثير | الصيغة |
|-------|------------|---------|--------|
| +1 | ≥ 4 | × 1.5 | مكافأة التعافي |
| +2 | ≥ 4 | × 2.0 | |
| +3 | ≥ 4 | × 2.5 | |
| +4 | ≥ 4 | × 3.0 | |
| −1 | ≥ 3 | ÷ 1.5 | تحذير الضعف المفاجئ |
| −2 | ≥ 3 | ÷ 2.0 | |
| −3 | ≥ 3 | ÷ 2.5 | |
| −4 | ≥ 3 | ÷ 3.0 | |
| 0 | أي | لا تغيير | تقدم اعتيادي |

التقييمات 1 و2 مستثناة من هذه المرحلة لأن التكرارات تُعاد ضبطها والفترة تُصبح 1 يوم تلقائياً.

**الصيغة العامة:**
```
المضاعف = 1 + (0.5 × |الفرق|)
إذا الفرق > 0:  فترة = round(فترة × المضاعف)
إذا الفرق < 0:  فترة = max(1, round(فترة / المضاعف))
```

### الخطوة 5 — السقف الديناميكي للفترة
يتمدد الحد الأقصى للفترة بشكل لوغاريتمي مع عدد المراجعات الناجحة:

```
درجة_الاستقرار = log₂(reps + 1)
الحد_الأقصى   = round(180 × max(1، درجة_الاستقرار))
الفترة         = min(الفترة، الحد_الأقصى)
```

| reps | درجة الاستقرار | الحد الأقصى |
|------|---------------|-------------|
| 1 | 1.0 | 180 يوم |
| 3 | 2.0 | 360 يوم |
| 7 | 3.0 | 540 يوم |
| 15 | 4.0 | 720 يوم |

### الخطوة 6 — عتبة اليوم (Daily Cooldown)
لن تُقترح الصفحة المُراجَعة اليوم مرة ثانية بنفس اليوم بغض النظر عن الفترة:

```
منتصف_الليل_القادم = اليوم الساعة 24:00:00
nextReview = max(الوقت_الحالي + الفترة_بالملليثانية، منتصف_الليل_القادم)
```

## 5. مثال رقمي كامل

**السيناريو:** صفحة كان المستخدم قد نسيها تماماً (EF = 1.3، النطاق 1)، ويُقيّمها الآن "ممتاز" (5) بعد مراجعة مكثفة.

```
الخطوة 1 — السجل: [...، 5]

الخطوة 2 — EF:
    config = { min: 2.6, max: 3.0, shift: +0.25 }
    EF_جديد = clamp(1.3 + 0.25، 2.6، 3.0)
            = clamp(1.55، 2.6، 3.0)
            = 2.6  ← يُسنَد فوراً إلى أدنى حد النطاق 5

الخطوة 3 — الفترة (reps=0):
    فترة = 1 يوم،  reps = 1

الخطوة 4 — القفز:
    نطاق_قديم = 1،  نطاق_جديد = 5،  الفرق = +4،  grade = 5
    المضاعف = 1 + (0.5 × 4) = 3.0
    فترة = round(1 × 3.0) = 3 أيام

الخطوة 5 — السقف: 3 < 180 → لا تغيير

الخطوة 6 — عتبة اليوم:
    nextReview = max(الآن+3أيام، منتصف الليل القادم)
               → غداً في أقرب حال
```

## 6. تصنيف الحوضات (getSmartPage)

قبل اختيار الصفحة، تُصنَّف جميع الصفحات المحفوظة في حوضات:

| الحوض | الشرط | وزن الأولوية |
|-------|-------|-------------|
| `intersection` | عضو في حوضين أو أكثر في نفس الوقت | **100** |
| `besieged` | صفحة ضعيفة بين جارتين قويتين | 80 |
| `due` | `nextReview ≤ الآن` | 60 |
| `risk` | EF ≤ 1.7 أو سجل متذبذب أو failureCount > 5 | 25 |
| `new` | `reps = 0` ولا يوجد `lastReview` | 15 |
| `shadow` | `interval ≥ 90` و`EF ≥ 2.6` (صفحة مستقرة، مراجعة مبكرة) | 5 |

**الصفحات الجديدة** لا تدخل حوض `intersection` أبداً — تُعالَج بشكل منفصل.

إذا كانت **جميع الحوضات فارغة** (المستخدم راجع كل شيء)، تُفعَّل استراتيجية الـ Fallback:
- تتخطى الصفحات التي راجعها اليوم (`lastReview ≥ بداية_اليوم`)
- تختار الصفحة ذات `nextReview` الأقرب (مراجعة مسبقة)
- إذا لم تتوفر بيانات SRS، تختار صفحة عشوائية لم تُراجَع

## 7. الاختيار الموزون داخل الحوض

بعد اختيار الحوض بالروليت الموزون، تُختار الصفحة داخله بأوزان خاصة:

### حوض `intersection`
```
الوزن = عدد_الحوضات × (أيام_التأخر + 1)^1.2 × (2.5 / EF)
إذا besieged في القائمة: الوزن × 1.5
إذا risk في القائمة:     الوزن × 1.3
```

### حوض `due`
```
أيام_التأخر = (الآن − nextReview) / 86400000
الوزن      = (أيام_التأخر + 1)^1.4 × (2.5 / EF)
إذا آخر_تقييم ≤ 3: الوزن × 1.5
إذا السورة مكتملة 80%+: الوزن × 2.0  ← إغلاق الحلقة
```

### حوض `risk` و`besieged`
```
الوزن = (2.6 − EF)² × (1 + failureCount / 10)
إذا besieged: الوزن × 2.0
```

### حوض `new`
```
الوزن = 10 (موحد)
```

### حوض `shadow`
```
الوزن = 2 (موحد)
```

## 8. كشف المحاصرة (_checkBesieged)

بعد كل حفظ، تُفحص الصفحات المحيطة بحثاً عن نمط "المحاصرة":

> الصفحة **محاصرة** إذا كانت ضعيفة (EF < 1.8) في حين أن جارتيها قويتان (EF > 2.5).

نطاق الفحص يتغير حسب التقييم:
- grade ≥ 4: فحص ±1 صفحة
- grade = 3: فحص ±2 صفحة
- grade < 3: فحص ±1 صفحة

عند اكتشاف المحاصرة: `isBesieged = true`
عند التعافي: تُحذف العلامة تلقائياً.

الصفحات المحاصرة تحصل على:
- مضاعف ×1.5 في حوض `intersection`
- مضاعف ×2.0 في حوض `besieged`

---

## 9. تأثير السورة (_applySurahImpact)

عند الفشل (grade < 3)، تُوزَّع عقوبة صغيرة على باقي صفحات نفس السورة:

| الجار | العقوبة |
|-------|---------|
| المباشر (±1 صفحة) | `−0.05` (مثل إزاحة تقييم "جيد") |
| بقية السورة | `−0.01` (خُمس الإزاحة) |

هذا يُجسِّد الترابط الواقعي بين صفحات السورة الواحدة في الحفظ.

---

## 10. مكافأة إغلاق الحلقة

عند الاختيار من حوض `due`، تحصل الصفحات التي تنتمي إلى سورة مكتملة **80% أو أكثر** (EF > 2.5) على مضاعف وزن **×2.0**. الهدف هو إعطاء الأولوية لاستكمال إتقان السورة كاملة بدلاً من التشتت بين صفحات متفرقة.

## 11. مخطط تدفق البيانات

```
المستخدم يُقيِّم صفحة
          │
          ▼
SRSService.saveSRS(pageId, rating)
          │
          ├─▶ calculateNext()
          │       ├─ تحديث السجل التاريخي
          │       ├─ Hard Clamp للنطاق الجديد
          │       ├─ حساب الفترة والتكرارات
          │       ├─ مضاعف القفز بين النطاقات (↑↓)
          │       ├─ السقف الديناميكي
          │       └─ عتبة اليوم (next midnight)
          │
          ├─▶ annotationService.saveSRSData()   → حفظ في localStorage
          ├─▶ _checkBesieged()                  → فحص وتحديث الجيران
          └─▶ _applySurahImpact()               → عقوبة السورة عند الفشل

الجلسة التالية
          │
          ▼
SRSService.getSmartPage(excludeIds)
          │
          ├─ تصنيف كل الصفحات في الحوضات
          ├─ روليت الحوضات الموزون
          ├─ اختيار موزون داخل الحوض
          └─ إرجاع الصفحة المختارة
```
